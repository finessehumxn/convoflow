    How it works

    How it holds together.

    1. Workers claim rows with FOR UPDATE SKIP LOCKED and write results in the same transaction, so a crash puts the batch back.
    2. Content-hash keys per tenant make replays safe.
    3. Row level security keeps tenants apart. Workers connect as a role that cannot bypass it.
    4. A batch the database rejects is retried row by row with backoff, so one bad row cannot block the rest. After 3 tries it goes to dead letters, which can be replayed.
    5. The scanner runs its rules inside Postgres every hour and stores evidence for each finding.
    6. Terraform for AWS (ECS Fargate on ARM, RDS, load balancer, autoscaling, CloudWatch alarms, GitHub OIDC deploys) is written and validated. This demo runs on Railway.
